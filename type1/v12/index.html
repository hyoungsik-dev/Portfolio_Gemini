ABOUT ME

경험에서 우러나온 개발 철학과 문제 해결 방식

01 · Philosophy

사용자 관점에서 출발하는 개발 철학

첫 회사에서 개발을 시작할 때부터 단순히 화면 정의서에 적힌 단위 기능만 기계적으로 구현하는 것에 안주하지 않았습니다. "실제 기업 고객들이 이 시스템을 어떤 목적과 비즈니스 플로우로 이용할까?"라는 호기심을 늘 품고 전체 사용자 여정을 먼저 파악하려 노력했습니다.

시스템이 만들어지는 근본적인 이유와 사용자 흐름을 먼저 이해하는 태도는, 단순한 코드 작성을 넘어 비즈니스의 가치를 명확히 담아내는 완성도 높은 시스템을 구축하는 단단한 밑거름이 되었습니다.

기능 구현을 넘어 비즈니스 목적과 사용자 흐름을 먼저 탐구하는 태도
02 · Ownership

내 코드에만 선 긋지 않고, 프로덕트 전체를 함께 고민하는 파트너

자사 서비스를 개발하며 단순히 주어진 내 백엔드 작업 범위에만 스스로를 가두지 않았습니다. "이 기능을 수정하면 다른 화면의 현황이나 연동된 메뉴들에서는 어떤 영향이 생길까?"를 전체적인 관점에서 늘 함께 고민했습니다.

서비스가 방대해질수록 기획자 혼자서는 놓치기 쉬운 시스템의 복잡한 연결고리나 화면 간의 불일치를 먼저 발견하고, "이 부분은 이렇게 맞춰보면 어떨까요?"라고 능동적으로 의견을 나누며 기획의 빈틈을 함께 채워나갔습니다.

내 업무의 경계를 넘어 서비스 완성도를 함께 빚어가는 동료
03 · Collaboration

각 포지션을 경청하고 파트 간 병목을 허무는 협업

백엔드 API 구축 타이밍이 전체 프로젝트 일정의 핵심 병목임을 깊이 이해하고 있습니다. 기획이 확정되면 프론트엔드 개발자가 지체 없이 작업할 수 있도록 초기에 집중하여 API를 선제적으로 완성해 두었습니다.

API 단위 검증에 그치지 않고, 프론트엔드 화면 구현 후 실제 웹에서 사용자 흐름을 따라 데이터 연동 상태를 직접 교차 검증하며 완성도를 챙겼습니다. 특히 이슈 관리 툴(Monday)에 등록되는 버그 중 프론트와 백엔드의 구분이 모호한 문제들을 먼저 디버깅하고 원인을 명확히 짚어주는 가교 역할을 도맡았습니다.

나아가 직접 경험해보지 않은 프론트엔드 기술이라도 JavaScript 기본기와 빠른 코드 파악 능력을 바탕으로, 자잘한 오류 수정과 데이터 연동 지원에 솔선수범하며 팀의 개발 완결성을 높였습니다.

API 선제 구축부터 낯선 영역의 이슈 해결 지원까지, 팀의 완결성을 높이는 협업
04 · Growth

특정 기술에 갇히지 않는 빠른 습득력과 확장성

6년 4개월간 C#과 .NET 환경을 중심으로 견고한 백엔드 시스템을 구축해 왔지만, 특정 프레임워크나 언어라는 틀에 스스로를 가두지 않습니다.

객체지향과 백엔드 아키텍처에 대한 탄탄한 기본기를 바탕으로, 팀과 비즈니스가 필요로 하는 새로운 언어나 프레임워크 기술이 주어지더라도 빠르게 흡수하여 실질적인 성과를 낼 준비가 되어 있습니다.

비즈니스 요구에 맞춰 빠르게 적응하고 성과를 내는 유연함
