01 · Core Philosophy

"단순히 코드를 구현하는 것에 머무르지 않고,
비즈니스의 본질적인 목적과 사용자 여정을 먼저 탐구합니다."

첫 회사에서 개발을 시작할 때부터 화면 정의서에 적힌 단위 기능만 기계적으로 구현하는 것에 안주하지 않았습니다. "실제 기업 고객들이 이 시스템을 어떤 목적과 비즈니스 플로우로 이용할까?"라는 질문을 늘 품고 전체 사용자 여정을 먼저 파악하려 노력했습니다.
시스템이 만들어지는 근본적인 이유와 데이터의 생애주기를 먼저 이해하는 태도는, 단순한 코드 작성을 넘어 비즈니스의 가치를 명확히 담아내는 완성도 높은 백엔드 아키텍처를 구축하는 단단한 밑거름이 되었습니다.
Engineering Journey Principle
1. 비즈니스 목적 및 데이터 흐름 파악 2. 전체 사용자 여정 분석 3. 가치 중심 시스템 및 API 구축
Engineering Process Diagram
1. 업무 요건 분석 및 데이터 모델링
2. 사이드 이펙트 & 시스템 연관 관계 선제 검토
3. 결함 사전 예방 및 무결한 아키텍처 착수
02 · Engineering Process

단순 구현을 넘어
업무 착수 전 시스템 전체를 검토하는 프로세스

새로운 요구사항이 주어졌을 때 단순히 코드 작성부터 서두르지 않습니다. 해당 개발이 시스템 전반에 미칠 사이드 이펙트(Side Effect)와 연동된 기능, 데이터 흐름 간의 연관 관계를 먼저 입체적으로 분석합니다.

작업 착수 전 잠재적인 예외 케이스와 데이터 정합성을 철저히 검토하고 시작함으로써, 개발 후 발생할 수 있는 결함을 사전에 예방하고 초기에 견고하고 무결한 시스템을 구축합니다.

업무 착수 전 사이드 이펙트를 선제 검토하여 결함을 원천 차단하는 개발 방식

CASE A · B2B SaaS & Performance 11,000+ 사업장 운영 · (주)유엔이
2023.04 ~ 2026.04

대용량 안전관리 데이터 누적 환경에서의 쿼리 튜닝 및 법정 보고서 엔진 최적화

중대재해처벌법 대비 11,000여 개 사업장의 일일 점검 데이터가 기하급수적으로 누적되는 환경에서, 복잡한 서식의 법정 안전관리 보고서(PDF/Excel) 생성 병목을 해결하고 시스템 응답성을 극대화한 핵심 사례입니다.

01. The Problem
점검 데이터 폭증 및 출력 지연
사업장별 안전점검, 교육, 협력사 이력 등 수십 개 테이블의 다중 조인 쿼리로 인해 보고서 출력 요청 시 DB CPU 급증 및 타임아웃 발생.
02. Architectural Solution
인덱스 재설계 및 비동기 파이프라인
MSSQL 실행 계획 분석을 통한 복합 인덱스(Covering Index) 재설계, 무결성 격리 트랜잭션 적용, 보고서 데이터 집계 로직 메모리 최적화.
03. Quantitative Impact
출력 속도 대폭 단축 & 96.6% 안정 지원
보고서 생성 응답 지연을 대폭 해소하고 대한산업안전협회 스마트 보고서 연동 후 사용률 약 96.6%를 무장애로 서포트.
Key Technical Decisions & Details
복합 인덱스 최적화: 날짜 및 사업장 ID 기준 조회 조건에 커버링 인덱스를 적용하여 테이블 풀 스캔(Table Full Scan) 방지
메모리 스트리밍 출력: 대용량 Excel/PDF 렌더링 시 메모리 누수를 막기 위해 파일 스트리밍 청크 단위 파이프라인 구성
원청-하청 권한 격리: 협력사 데이터 접근 시 법적 요건에 맞춘 철저한 RBAC 권한 검증 및 데이터 무결성 보장
통계 대시보드 쿼리 경량화: 어드민 대시보드 집계 쿼리를 사전 집계 뷰 및 캐싱 구조로 분리하여 메인 DB 부하 분산
CASE B · Modernization & Architecture 대기업·공공 SI 프로젝트 전수 완결 · 케이알피스인포텍
2020.01 ~ 2023.02

레거시 시스템의 현대적 리팩토링 및 선제적 RESTful API 설계

오래된 Classic ASP 기반 레거시 시스템의 복잡한 비즈니스 로직을 .NET Core 환경으로 안정적으로 현대화하고, 프론트-백엔드 간 병목을 없애는 선제적 API 설계 프로세스를 구축한 사례입니다.

01. The Problem
레거시 결합도 및 일정 병목
화면과 DB 로직이 강하게 결합된 Classic ASP 구조로 인해 유지보수 공수가 높았으며, 백엔드 API 개발 지연 시 프론트 작업이 중단되는 병목 발생.
02. Architectural Solution
계층형 아키텍처 & Mock API 선제 구축
ASP.NET Core 및 EF Core 기반의 계층형 아키텍처로 비즈니스 로직을 분리하고, 기획 확정 즉시 표준 RESTful API 규격을 선제 배포.
03. Quantitative Impact
프론트 대기 제로 & 11개 프로젝트 완결
프론트엔드 개발자의 백엔드 대기 시간을 없애고, 현대건설·한화생명 등 11개 대기업 프로젝트를 일정 내 무결점으로 릴리즈 완료.
Key Technical Decisions & Details
점진적 마이그레이션 전략: 업무 중단 없이 핵심 근무시간 산정 및 계정 관리 로직을 모듈 단위로 .NET Core로 안전하게 이관
표준화된 API 응답 규격: 상태 코드, 공통 에러 포맷, 페이징 규격을 통일하여 프론트엔드 연동 에러 70% 이상 감소
실시간 데이터 연동 (KOVO 연맹): 배구단 공식 웹 구축 시 외부 연맹 데이터 동기화 예외 처리 및 재시도 메커니즘 구축
트랜잭션 정합성 보호: 자산 관리 및 근무시간 상한제 시스템의 중요 수정 이력을 원자적(ACID)으로 완벽 보존
