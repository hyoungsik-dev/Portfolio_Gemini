Chapter 01 · Philosophy

"단순히 코드를 구현하는 것에 머무르지 않고,
비즈니스의 본질적인 목적과 사용자 여정을 먼저 탐구합니다."

첫 회사에서 개발을 시작할 때부터 단순히 화면 정의서에 적힌 단위 기능만 기계적으로 구현하는 것에 안주하지 않았습니다. "실제 기업 고객들이 이 시스템을 어떤 목적과 비즈니스 플로우로 이용할까?"라는 호기심을 늘 품고 전체 사용자 여정을 먼저 파악하려 노력했습니다.
시스템이 만들어지는 근본적인 이유와 사용자 흐름을 먼저 이해하는 태도는, 단순한 코드 작성을 넘어 비즈니스의 가치를 명확히 담아내는 완성도 높은 시스템을 구축하는 단단한 밑거름이 되었습니다.

Chapter 02 · Engineering Process

단순 구현을 넘어
업무 착수 전 시스템 전체를 검토하는 프로세스

새로운 업무나 요구사항이 주어졌을 때 단순히 코드 작성부터 서두르지 않습니다. 해당 개발이 시스템 전반에 미칠 사이드 이펙트(Side Effect)와 연동된 기능, 데이터 흐름 간의 연관 관계를 먼저 입체적으로 분석합니다.

작업 착수 전 잠재적인 예외 케이스와 데이터 정합성을 철저히 검토하고 시작함으로써, 개발 후 발생할 수 있는 결함을 사전에 예방하고 초기에 견고하고 무결한 시스템을 구축합니다.

업무 착수 전 사이드 이펙트와 시스템 연관 관계를 선제 검토하여 결함을 예방하는 개발 프로세스

Chapter 03 · Collaboration

각 포지션을 경청하고
파트 간 병목을 허무는 협업

백엔드 API 구축 타이밍이 전체 프로젝트 일정의 핵심 병목임을 깊이 이해하고 있습니다. 기획이 확정되면 프론트엔드 개발자가 지체 없이 작업할 수 있도록 초기에 집중하여 API를 선제적으로 완성해 두었습니다.

API 단위 검증에 그치지 않고, 프론트엔드 화면 구현 후 실제 웹에서 사용자 흐름을 따라 데이터 연동 상태를 직접 교차 검증하며 완성도를 챙겼습니다. 특히 이슈 관리 툴(Monday)에 등록되는 버그 중 프론트와 백엔드의 구분이 모호한 문제들을 먼저 디버깅하고 원인을 명확히 짚어주는 가교 역할을 도맡았습니다.

나아가 직접 경험해보지 않은 프론트엔드 기술이라도 JavaScript 기본기와 빠른 코드 파악 능력을 바탕으로, 자잘한 오류 수정과 데이터 연동 지원에 솔선수범하며 팀의 개발 완결성을 높였습니다.
